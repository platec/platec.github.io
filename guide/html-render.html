HTML 渲染（DOM 叠加） ​

有些内容用 Canvas 画并不划算：复杂文字排版、表单控件、第三方图表库、视频，或需要浏览器原生交互的富组件。renderHTML 让某个元素的内容改由一层真实 DOM 呈现——这层 DOM（HtmlOverlay）覆盖在 canvas 之上，随视口平移 / 缩放实时同步位姿与尺寸；配置了 renderHTML 的元素在 canvas 侧不再绘制位图 / 矢量内容。

启用方式 ​

renderHTML 可以挂在 Image（作为与 width / height 同级的 prop），也可以通过样式键设置在任意元素上：

ts
import { Image, registerHTMLRenderer } from '@leaf-plus/core';

// 1) Image prop（随图纸序列化）
const card = new Image();
card.setPosition(120, 60);
card.setSize(200, 110);
card.setRenderHTML('demo-kpi');   // 注册名
card.a('label', 'CPU 使用率');
card.a('value', 62);
storage.add(card);

// 2) 样式键（随图纸序列化）
shape.s('renderHTML', 'demo-kpi');

renderHTML 取值（HTMLRendererSource）支持四种形态：

形态说明可序列化
注册名字符串registerHTMLRenderer(name, ...) 注册过的名字✅
源码字符串一段返回 DOM 的函数体 / 函数字面量（由 new Function 编译）✅
渲染函数(element, view) => HTMLElement | null❌ 仅运行时
定义对象{ render, update?, dispose?, keys?, styleKeys?, resizeAware? }❌ 仅运行时

字符串形态是注册名或 JS 源码，不是原始 HTML 片段。想内联一段 HTML，请在源码里构造 DOM 后 return： "const d=document.createElement('div'); d.innerHTML='<b>Hi</b>'; return d;"。

注册渲染器 ​

命名渲染器可随图纸 JSON 序列化（图纸里只存名字），因此推荐用注册名的方式：

ts
import { registerHTMLRenderer } from '@leaf-plus/core';

registerHTMLRenderer('demo-kpi', {
  render(element, view) {
    const div = document.createElement('div');
    div.className = 'kpi-card';
    div.textContent = `${element.a('label')}: ${element.a('value') ?? 0}%`;
    return div;                       // 返回 DOM 根节点
  },
  update(dom, element, view) {        // 可选：键变化时就地更新，避免重建 DOM
    dom.textContent = `${element.a('label')}: ${element.a('value') ?? 0}%`;
  },
  dispose(dom) { dom?.remove(); },    // 可选：宿主被回收时释放外部资源
  keys: ['label', 'value'],           // 仅这些 attr 键变化才刷新内容
  styleKeys: [],                      // 依赖的样式键（可选）
  resizeAware: false,                 // true 时元素尺寸变化也触发内容刷新
});
定义字段说明
render(element, view)必选，返回要叠加的 DOM 根节点（非 DOM / 抛错时安全降级为无内容）
update(dom, element, view)可选，内容键变化时就地更新既有 DOM（提供后不重建节点）
dispose(dom)可选，元素移除 / 销毁 / 视图销毁时回收，释放定时器、播放器等外部资源
keys依赖的 attr 键；缺省时按元素全部 attrs 计算内容键
styleKeys依赖的样式键
resizeAware为 true 时元素尺寸变化也计入内容键（默认只同步宿主尺寸样式，不重渲染）

更新机制（内容键） ​

HtmlOverlay 不会每帧重建 DOM。它为每个宿主维护一个内容键（contentKey）：

  • 内容键由 keys（或全部 attrs）+ styleKeys +（resizeAware 时的宽高）计算。
  • 键不变 → 完全不调用 render / update。
  • 键变化 → 有 update 则就地更新，否则重建 DOM。
  • 每帧只做一次位姿字符串（transformKey）比较，相等则连 style 都不写。

所以声明精确的 keys 能显著减少 DOM 操作。需要手动强制刷新时可调用 view.htmlOverlay?.markDirty(element)。

解析优先级 ​

getHTMLRenderer(element) 按以下顺序取渲染器：

  1. 元素自身的 renderHTML prop（Image.setRenderHTML / 运行时赋值）
  2. element.s('renderHTML') 样式（注册名或源码，随图纸序列化）
  3. element.a('renderHTML') 属性（矢量图标 bind 默认值通道）
  4. 图标资源顶层的 renderHTML 定义（JSON 内嵌代码字符串）

命中与序列化 ​

  • 命中：配置了 renderHTML 的元素 canvas 侧无像素，命中统一按包围盒（OBB）判定，不走 pixelPerfect。
  • 序列化：注册名 / 源码字符串随图纸 JSON 往返；函数 / 定义对象仅运行时有效。
  • 导出：HTML 叠加层不属于 Canvas 像素，导出 PNG / SVG 时需要单独合成（编辑器用 html-to-image 处理），详见 导出与独立绘制。

相关 API ​

registerHTMLRenderer / unregisterHTMLRenderer / getRegisteredHTMLRenderer，类型 HTMLRenderFunction / HTMLUpdateFunction / HTMLRendererDefinition / HTMLRendererSource。完整签名见 API 参考：工具函数。
